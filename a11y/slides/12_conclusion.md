# Conclusion

- Accessibility should not be a constraint, it is an **investment**
- Always favor native HTML elements over an extra layer
- Get into the habit of writing semantic HTML
- Audit your applications often (automated + manual)
- Learn from your mistakes

---

# Good practices

- In real projects, we recommend:
  - using a **Design System** to document your components
  - building accessibility directly into your components (see the ARIA - Web Components chapter)
  - setting up **regular checkpoints** to ensure the quality of the project
  - automating accessibility tests in your **CI/CD**

---

# Summary checklist

- ✅ Set `lang` on `<html>` and a descriptive `<title>`
- ✅ Use landmarks (`header`, `nav`, `main`, `footer`)
- ✅ Respect the heading hierarchy (h1 → h2 → h3)
- ✅ Provide an `alt` for every image
- ✅ Use `<button>` for actions, `<a>` for navigation
- ✅ Associate every field with a `<label>`
- ✅ Ensure sufficient contrast (minimum 4.5:1)
- ✅ Keep focus always visible
- ✅ Respect user preferences (dark mode, animations)
- ✅ Test keyboard navigation and with a screen reader
