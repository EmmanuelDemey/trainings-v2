# Conclusion

- L'accessibilité ne doit pas être une contrainte, c'est un **investissement**
- Toujours privilégier les éléments HTML natifs plutôt qu'une surcouche
- Prenez l'habitude d'écrire du code HTML sémantique
- Auditez souvent vos applications (automatique + manuel)
- Apprenez de vos erreurs

---

# Bonnes pratiques

- Dans de vrais projets, nous recommandons :
  - l'utilisation d'un **Design System** afin de documenter vos composants
  - d'intégrer l'accessibilité directement dans vos composants (cf. chapitre ARIA - Web Components)
  - de mettre en place des **points de contrôles réguliers** afin de s'assurer de la qualité du projet
  - d'automatiser les tests d'accessibilité dans votre **CI/CD**

---

# Checklist récapitulative

- ✅ Définir `lang` sur `<html>` et `<title>` descriptif
- ✅ Utiliser les landmarks (`header`, `nav`, `main`, `footer`)
- ✅ Respecter la hiérarchie des titres (h1 → h2 → h3)
- ✅ Fournir un `alt` pour toutes les images
- ✅ Utiliser `<button>` pour les actions, `<a>` pour la navigation
- ✅ Associer tous les champs avec des `<label>`
- ✅ Assurer un contraste suffisant (minimum 4.5:1)
- ✅ Rendre le focus toujours visible
- ✅ Respecter les préférences utilisateur (dark mode, animations)
- ✅ Tester la navigation au clavier et avec un lecteur d'écran
