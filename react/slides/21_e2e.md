# 21 - End-to-end testing with Cypress

---

# Learning objectives

At the end of this chapter, you will be able to:

- **Place** end-to-end tests in the testing pyramid, and decide what deserves one
- **Install** and **configure** Cypress 16 for a Vite app (`cypress.config.ts`, `baseUrl`)
- **Write** specs with accessible queries (`cy.getByRole`) and retried assertions
- **Control** the network with `cy.intercept` — stub, wait, assert on requests
- **Factor** repeated steps into typed **custom commands**
- **Run** the suite in CI against a started server, and **compare** with Playwright

# Installation and configuration

```bash
npm install -D cypress
npx cypress open          # first run: scaffolds cypress.config.ts and cypress/
```

```ts
// cypress.config.ts
import { defineConfig } from 'cypress';

export default defineConfig({
  e2e: {
    baseUrl: 'http://localhost:5173',          // cy.visit('/') resolves against it
    specPattern: 'cypress/e2e/**/*.cy.ts',
    supportFile: 'cypress/support/e2e.ts',
  },
  expose: { apiUrl: '/api' },                  // public values: Cypress.expose('apiUrl')
  video: false,
});
```

- `cypress/e2e/` — the specs; `cypress/support/` — commands and global hooks;
  `cypress/fixtures/` — JSON data for stubs
- Cypress **does not start your app**: the dev server (or `vite preview`) must be up
- Secrets go through **`cy.env(['TOKEN'])`** (async); public config through
  **`Cypress.expose()`**

# A first spec

```ts
// cypress/e2e/people.cy.ts
describe('People list', () => {
  beforeEach(() => {
    cy.visit('/');
  });

  it('filters the people by name', () => {
    cy.getByRole('textbox', { name: 'Search' }).type('sky');

    cy.getByRole('row').should('have.length', 2);                 // header + Luke
    cy.getByRole('cell', { name: 'Luke Skywalker' }).should('be.visible');
  });

  it('opens the detail page of a person', () => {
    cy.getByRole('link', { name: 'Luke Skywalker' }).click();

    cy.location('pathname').should('eq', '/people/1');
    cy.getByRole('heading', { name: 'Luke Skywalker' }).should('be.visible');
  });
});
```

- Mocha's `describe` / `it` / `beforeEach`, Chai assertions through `.should()`
- Each test starts on a **fresh page**: cookies, `localStorage` and session storage are cleared

# Commands are queued, assertions retry

```ts
cy.getByRole('button', { name: 'Save' })   // 1. enqueued, not run yet
  .click();                                // 2. enqueued

cy.contains('Saved').should('be.visible'); // 3. retried until true… or 4 s
```

- `cy.*` calls **enqueue** commands; Cypress runs them later, one after the other
- Queries (`get`, `getByRole`, `contains`, `find`) and their `.should()` **retry**
  until the assertion passes or `defaultCommandTimeout` (4 s) expires
- So **no `async`/`await`**, no `const el = cy.get(…)`: chain, or use `.then()`
- Never `cy.wait(2000)`: wait for **something** — an element, a route alias

```ts
cy.getByRole('cell').its('length').then((count) => {
  cy.log(`${count} cells`);
});
```

# Querying like a user

```ts
cy.getByRole('button', { name: 'Create' });                  // built in since Cypress 16
cy.getByRole('textbox', { name: /name/i });
cy.get('nav').getByRole('link', { name: 'People' });         // scoped to an element
cy.getByRole('dialog', { name: 'Delete', native: false });   // role from an ARIA attribute

cy.contains('button', 'Create');                             // element + text
cy.get('[data-cy=people-table]');                            // last resort: a test id
```

- **`cy.getByRole`** — native in Cypress 16: the role + the **accessible name**,
  as in Testing Library. `native: false` also matches `role="…"` attributes
- Avoid CSS classes and DOM structure: they change with the styling
- Before Cypress 16: `@testing-library/cypress` (`cy.findByRole`)
- Keyboard: `cy.press(Cypress.Keyboard.Keys.TAB)` sends real key events

# Forms and assertions

```ts
it('creates a person', () => {
  cy.visit('/create');

  cy.getByRole('textbox', { name: 'Name' }).type('Ahsoka Tano');
  cy.getByRole('spinbutton', { name: 'Height' }).type('170');
  cy.getByRole('combobox', { name: 'Gender' }).select('female');
  cy.getByRole('button', { name: 'Create' }).click();

  cy.location('pathname').should('match', /^\/people\/\w+$/);
  cy.getByRole('heading', { name: 'Ahsoka Tano' }).should('be.visible');
});

it('shows an error when the name is empty', () => {
  cy.visit('/create');
  cy.getByRole('button', { name: 'Create' }).click();

  cy.getByRole('textbox', { name: 'Name' }).should('have.attr', 'aria-invalid', 'true');
  cy.contains('Name is required').should('be.visible');
});
```

- `.type()`, `.clear()`, `.check()`, `.select()`, `.selectFile()` — real events
- Common assertions: `be.visible`, `exist`, `have.text`, `have.value`,
  `have.attr`, `be.disabled`, `have.length`

# The network — `cy.intercept`

```ts
it('shows the people returned by the API', () => {
  cy.intercept('GET', '/api/people', { fixture: 'people.json' }).as('getPeople');

  cy.visit('/');
  cy.wait('@getPeople');

  cy.getByRole('row').should('have.length', 4);
});

it('shows an error when the API fails', () => {
  cy.intercept('GET', '/api/people', { statusCode: 500 }).as('getPeople');

  cy.visit('/');

  cy.getByRole('alert').should('contain', 'Cannot load people');
});
```

- **Stub** a response (`fixture`, `body`, `statusCode`, `delay`) — deterministic tests,
  error states on demand
- **Spy** without stubbing: `cy.intercept('POST', '/api/people').as('create')`
- `cy.wait('@alias')` waits for the request and yields it:
  `.its('request.body').should('deep.include', { name: 'Ahsoka Tano' })`
- Declare intercepts **before** the action that triggers the request

# Custom commands

```ts
// cypress/support/commands.ts
Cypress.Commands.add('searchPerson', (name: string) => {
  cy.getByRole('textbox', { name: 'Search' }).clear().type(name);
});

declare global {
  namespace Cypress {
    interface Chainable {
      /** Types `name` in the search field of the people list. */
      searchPerson(name: string): Chainable<void>;
    }
  }
}
export {};
```

```ts
// cypress/support/e2e.ts
import './commands';
```

```ts
cy.visit('/');
cy.searchPerson('vader');
```

- One **user-level** step per command: `login`, `searchPerson`, `createPerson`
- The `declare global` block types `cy.searchPerson` in every spec
- **`cy.session(id, setup)`** caches a login across tests: setup runs once

# TypeScript and project layout

```json
// cypress/tsconfig.json
{
  "extends": "../tsconfig.json",
  "compilerOptions": { "types": ["cypress"], "isolatedModules": false },
  "include": ["**/*.ts"]
}
```

- A **separate** `tsconfig` for `cypress/`: Cypress's global `expect` (Chai)
  clashes with Vitest's — keep them in different projects
- Exclude `cypress/` from the app's `tsconfig` and from `vitest.config.ts`
- Scripts:

```json
{
  "scripts": {
    "e2e": "start-server-and-test dev http://localhost:5173 'cypress run'",
    "e2e:open": "start-server-and-test dev http://localhost:5173 'cypress open'"
  }
}
```

- `start-server-and-test` starts the server, waits for the URL, runs Cypress,
  stops the server

# Running in CI

```yaml
# .github/workflows/e2e.yml
jobs:
  cypress:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: cypress-io/github-action@v7
        with:
          build: npm run build
          start: npx vite preview --port 5173
          wait-on: 'http://localhost:5173'
```

- `cypress run` — **headless**, Electron by default, `--browser chrome|firefox|edge`
- The official action installs, caches the binary, starts the server and waits
- On failure: **screenshots** automatically, videos with `video: true`
- Run e2e against the **production build** (`vite preview`), not only the dev server
- Flaky test? `retries: { runMode: 2 }` hides it — fix the missing wait instead

# Playwright — the alternative

```ts
// e2e/people.spec.ts
import { expect, test } from '@playwright/test';

test('filters the people by name', async ({ page }) => {
  await page.goto('/');
  await page.getByRole('textbox', { name: 'Search' }).fill('sky');

  await expect(page.getByRole('row')).toHaveCount(2);
  await expect(page.getByRole('cell', { name: 'Luke Skywalker' })).toBeVisible();
});
```

```ts
// playwright.config.ts
export default defineConfig({
  use: { baseURL: 'http://localhost:5173' },
  webServer: { command: 'npm run dev', url: 'http://localhost:5173', reuseExistingServer: true },
  projects: [{ name: 'chromium', use: devices['Desktop Chrome'] }],
});
```

- `async`/`await` instead of a command queue; **auto-waiting** locators and web-first assertions
- Chromium, Firefox **and WebKit**, in parallel; `webServer` starts the app itself
- `npx playwright test --ui`, `codegen`, a **trace viewer** for failures; `page.route()` stubs the network

# Cypress or Playwright?

<br />

| | Cypress | Playwright |
|---|---|---|
| Runs | **in** the browser, next to the app | drives the browser from Node |
| Style | command chain, implicit retries | `async`/`await`, auto-waiting |
| Browsers | Chrome family, Firefox, WebKit (experimental) | Chromium, Firefox, WebKit |
| Multi-tab / multi-origin | limited (`cy.origin`) | native |
| Parallelism | Cypress Cloud (💰) or sharding | built in, free |
| Debugging | time-travel UI, live reload | UI mode, trace viewer |
| Component tests | yes | experimental |

<br />

- Both are good: pick one per project, write specs **like a user** (roles, names)
- The same journeys, the same rules: few tests, critical paths, network under control

# Recap

- E2E tests run the **whole app** in a **real browser**: few of them, for
  critical journeys
- `cypress.config.ts`: `baseUrl`, `specPattern`, `supportFile`; the app must be
  **running** — `start-server-and-test` or the GitHub action
- Commands are **queued**; queries and `.should()` **retry** — never `cy.wait(ms)`
- Query **like a user**: `cy.getByRole(role, { name })`, built into Cypress 16
- **`cy.intercept`** stubs or spies on requests; `cy.wait('@alias')` synchronizes
- **Custom commands** (+ a `Chainable` declaration) for user-level steps;
  `cy.session` for logins
- **Playwright**: same goals, `async`/`await`, three engines, parallel by default

# Quiz — Question 1 / 3

```ts
const button = cy.getByRole('button', { name: 'Save' });
button.click();
```

**Why is this a smell in Cypress?**

- **A.** `getByRole` does not exist in Cypress
- **B.** `cy.*` returns a **chainable** that enqueues commands, not the element —
  storing it suggests it is a value you can reuse later
- **C.** `click()` needs `await`
- **D.** It is slower than `cy.get('button')`

<v-click>

> ✅ **B** — Cypress commands are enqueued and run later. Chain them
> (`cy.getByRole(…).click()`), use an alias (`.as('save')` then `cy.get('@save')`),
> or `.then()` to work with the yielded element.

</v-click>

# Quiz — Question 2 / 3

**A test sometimes fails because the table is empty when it asserts. What is the
right fix?**

- **A.** `cy.wait(3000)` before the assertion
- **B.** Increase `defaultCommandTimeout` to 60 s
- **C.** `cy.intercept` the request with an alias, then `cy.wait('@getPeople')` —
  or assert on the expected rows, which retries
- **D.** Add `retries: 3` to the config

<v-click>

> ✅ **C** — Wait for an **event**, not for a duration. A fixed wait is slow
> *and* still flaky; retries and long timeouts hide the race instead of fixing it.

</v-click>

# Quiz — Question 3 / 3

**`npx cypress run` fails with "Cypress could not verify that this server is
running: http://localhost:5173". Why?**

- **A.** Cypress only supports port 3000
- **B.** Cypress does not start the application — start it first (or use
  `start-server-and-test` / the CI action's `start` option)
- **C.** `baseUrl` must point to the `dist/` folder
- **D.** The Cypress binary is not installed

<v-click>

> ✅ **B** — Cypress tests a running site. Playwright's `webServer` option can
> start it for you; with Cypress, a wrapper script or the GitHub action does.

</v-click>
