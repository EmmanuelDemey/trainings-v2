# Training objectives

- **Create and tool** a React project with Vite, TypeScript, oxlint and oxfmt
- **Build** an interface out of small, typed, **function components**
- **Manage state** — local with hooks, shared with Context, global with Zustand or
  Redux Toolkit, server-side with **TanStack Query**
- **Fetch data** robustly: loading and error states, cancellation, error boundaries,
  `Suspense`
- Structure a multi-page application with **React Router**, translate it, and
  build **accessible, validated forms**
- **Test** at every level: Vitest and Testing Library, Storybook, Cypress
- **Ship** it: a Docker image, Kubernetes manifests, and a health check with
  React Doctor

<br />

> This training is based on **React 19.3**, **Vite 8**, **TypeScript 7**,
> **Vitest 5**, **React Router 8**, **TanStack Query 5**, **Zustand 5**,
> **Material UI 9**, **Storybook 10** and **Cypress 16**.

# Prerequisites

- Solid knowledge of **JavaScript** — no prior React experience required
- Comfortable with **HTML**, **CSS** and the command line
- Some notions of **TypeScript** help, but chapter 2 covers what you need
- A **laptop** with Node.js >= 22.22.2 installed (24.15+ recommended), Git, and
  an editor (VS Code or WebStorm)
- The **React Developer Tools** browser extension (Chrome, Firefox or Edge)

---

# TypeScript in this training

- **All code snippets are written in TypeScript** (`.ts` / `.tsx`) — closer to
  real-world projects
- React's types come from **`@types/react`**; most of the time, inference does the work:

```tsx
import { useState } from 'react';

type CounterProps = { initial?: number };

export function Counter({ initial = 0 }: CounterProps) {
  const [count, setCount] = useState(initial);   // number, inferred
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

- Vite only **strips** the types; the type check is a separate command:

```bash
tsc --noEmit      # npm run typecheck
```

# How the three days run

| | Chapters | Hands-on |
|---|---|---|
| **Day 1** | 0 → 8 — setup &amp; tooling, TypeScript, unit testing, modern JS, JSX, components, styling, hooks | TP 1 → TP 8 |
| **Day 2** | 9 → 15 — data fetching, error boundaries, custom hooks, state management, Suspense, router, i18n | TP 9 → TP 15 |
| **Day 3** | 16 → 24 — forms, TanStack Query, UI library, Zustand, Storybook, e2e, Docker, React Doctor, what's new | TP 16 → TP 23 |

<br />

- Each chapter is followed by its **hands-on session**, on its own standalone
  project — roughly half the time
- Each chapter closes with a **quiz** corrected together, each day with a **retro**
- Day 3 is **à la carte**: the group picks the topics that matter most for its projects

# Teaching methods

- Alternation between **theoretical lectures** and **hands-on practice**
- **Live coding** of the key examples
- Workshops and practical exercises, with a worked **solution** for each one
- Field experience feedback from the trainer
- Digital course materials provided

<br />

# Evaluation

- A **self-assessment questionnaire** before the session
- A short **formative quiz** closing each chapter, corrected together
- Continuous evaluation through **workshops, exercises and practical work** — the
  specs of each workshop tell you when you are done
- A **final questionnaire** mirroring the self-assessment, to measure progress

# The workshop projects

- **Twenty-three standalone workshops**, one per chapter, under `workshops/`, each
  its own Vite project — no import between them, take them in any order:

```bash
cd 08_hooks
npm install
npm run dev          # http://localhost:5173
npm test             # vitest run — the specs that grade the workshop
npm run typecheck    # tsc --noEmit
```

- The code ships as a **working app with `// TODO` markers**; the steps are
  described in each workshop's `README.md`, and the worked answer lives in
  `solutions/`, in a folder of the same name
- Every workshop uses the same domain: the **Star Wars people** — a table, a
  filter, a person detail, a creation form
- `node check-env.mjs --install` (at the root of the workshops folder) checks your
  machine and pre-installs every workshop — ideally **run a week before** the session

# The toolchain

| Tool | Version | Role |
|---|---|---|
| **React** | 19.3 | The UI library — `react` + `react-dom` |
| **Vite** | 8 | Dev server and production bundler |
| **TypeScript** | 7 | Static types, checked with `tsc --noEmit` |
| **Vitest** | 5 | Test runner, reuses the Vite config |
| **Testing Library** | 16 | Renders components and queries them like a user |
| **jsdom** | 30 | A browser-like DOM for the tests, in Node.js |

<br />

- Every workshop pins these versions in its own `package.json` and
  `package-lock.json`: `npm install` gives everyone the same setup
- `.nvmrc` in each folder: `nvm use` picks the right Node.js version
